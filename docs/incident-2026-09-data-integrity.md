# 2026年9月 データ信頼性インシデント — 何が起き、何を変えたか

読者からの指摘をきっかけに全件検証を行った結果、TORAN のデータと表示の両方に
構造的な欠陥が見つかった。このドキュメントは、**起きたことの記録**と、
**同じことを繰り返さないための判断基準**をまとめたものである。

作業ログではない。次に同種の判断を迫られたとき、何を疑い、何を確かめるかの指針として書いている。

---

## 1. 何が起きたか

### 1-1. 出典の創作（evidence 102件を削除）

「国土交通省 政策実績アーカイブ」「復興庁 政策実績白書」「福島県庁実績」——
官公庁の刊行物らしい名前が出典欄に並んでいた。**いずれも検索しても実在しない。**
もっともらしい名称を組み立てただけのものだった。

出典が創作されていたということは、記述の中身も裏付けを持っていなかった。実際、
検証すると次のような誤りが含まれていた。

| 種類 | 件数 | 例 |
|---|---|---|
| 在任した事実のない役職 | 16 | 中司宏「厚生労働大臣」（当時は枚方市長）、宮沢洋一「財務大臣」（実際は経産相） |
| 在任時期が一致しない | 4 | 高村正大は記載時点で外務政務官ではなく財務政務官 |
| 所管外・裏付けなし | 19 | |
| 検証可能な事実を述べていない | 20 | 「政策調整を統括」「防災対策の調整」 |
| 出典が資料体の名称のみ | 40 | `src:"参議院会議録"` のみ。会期も委員会も日付もない |

`src:"参議院会議録"` の40件には、横沢高徳（元モトクロス選手・パラリンピアン）に
「知事経験に基づく」、山田吉彦（2025年7月初当選）に「大臣としての経験を活かし」など、
**当人の経歴と正面から矛盾する記述**が含まれていた。

### 1-2. 裏付けのない評価点（445人）

evidence を1件も持たない議員が445人（全781人の57%）いた。それでも8軸評価と
総合スコアは付いていた。評価点は8軸の合計から機械的に算出されるため、
**軸に裏付けがなければ点数にも裏付けがない。**

### 1-3. 重複レコード（9組）

参議院の登録名（ひらがな通称）と本名（漢字）が別人として二重登録されていた。
議員総数が790人と表示されていたが、実際は781人だった。かごしま彰宏は2レコードで
評価が57点と77点に食い違っており、どちらも裏付けを持っていなかった。

### 1-4. 出典が一度もリンクになっていなかった

最も根深い欠陥。詳細ページの描画コードはこうなっていた。

```js
${e.src ? `<span>📎 ${e.src}</span>` : ''}
```

`e.url` がどこからも参照されていない。**evidence 552件のうちURLを持つ380件すべてが、
読者から辿れなかった。** 📎アイコンが付いているためリンクがあるように見え、
かえって誤解を招いていた。

一次情報のURLを付ける作業を何度も重ねてきたが、その成果はサイト上に一切出ていなかった。
出典を検証可能にするという TORAN の根幹が機能していなかったことになる。

### 1-5. data_core.js の同期漏れ

議員一覧ページは `data.js` ではなく `data_core.js` を読み込む。evidence 101件を
削除した際に `data_core.js` へ反映し忘れ、一覧の「根拠」件数が830件（実際は552件）の
まま表示されていた。

### 1-6. 壊れた script タグ

`politicians.html` に中身が「〜」だけの `<script>` タグが混入しており、
ページ読み込みのたびにJSエラーを出していた。

## 2. なぜ見逃されたか

### 2-1. CIがデータ整合性しか見ていなかった

`validate_data.py` は total と axes の算術的な整合を検査する。だが
**「その数字に根拠があるか」は検査していなかった。** 裏付けゼロの議員に60点が
付いていても、60 = axes合計×100/40 が成り立っていればCIは緑になる。

同じ構造で、描画層は一切テストされていなかった。出典が `<span>` のままでも、
レーダーが壊れても、CIは緑のままだった。

### 2-2. 出典名の「もっともらしさ」が検証の代わりになっていた

「国土交通省 政策実績アーカイブ」という文字列は、一見すると出典として機能している
ように見える。**出典欄が埋まっていることと、出典が存在することは別**なのに、
前者で後者が満たされたことにしていた。

### 2-3. 検出ルールが狭すぎた

再発防止のCIを入れた直後、そのルール自体に穴が見つかった。
実在しない文書名を**末尾一致**（`/政策実績白書$/`）で検出していたため、
「復興庁 政策実績白書**資料**」のように語尾を1語足しただけの出典が素通りしていた。

**ルールを書いたら、そのルールをすり抜ける書き方を自分で考えること。**

### 2-4. 正本が1つではなかった

`data.js` / `data_core.js` / `politicians_base.json` の3つに同じ議員データが
入っており、どれか1つだけ直しても他が古いまま残る構造だった。

## 3. これから守ること

### 3-1. 出典は「実在するページのURL」で書く

```
✗ 国土交通省 政策実績アーカイブ     ← 検索しても存在しない
✗ 参議院会議録                      ← どの会期・委員会・日付か特定できない
✗ 福島県庁実績                      ← 県庁は「実績」という刊行物を出していない
✓ 石川県 石川県創造的復興プラン + https://www.pref.ishikawa.lg.jp/...
```

**出典名を思いつきで組み立てない。** 実在を確認したページのURLを書く。

### 3-2. 検証可能な命題だけを書く

```
✗ 経済財政担当大臣として政策調整を統括
✗ 地域インフラ整備や防災対策の調整
```

これらは正しいとも誤りとも言えない。**法案名・予算額・日付・閣議決定名・施設名の
いずれかを含まない記述は書かない。**

### 3-3. 役職と在任時期を必ず照合する

役職名だけ見ると妥当でも、時期を合わせると破綻している例が多かった。

- 在任**後**の出来事を実績にしない（ラピダス設立は梶山弘志の退任10か月後、
  3か年緊急対策の完了は石井啓一の退任1年半後）
- 地方自治体の長としての実績を国会議員の実績欄に書かない

### 3-4. 裏付けのない評価点を付けない

evidence が0件の議員には `total:null / rank:"" / axes:null / survey:"未評価"` を入れ、
サイト上は「評価なし（裏付け資料の確認中）」と表示する。
**点数を空欄にするのは敗北ではなく、正直さの表明である。**

### 3-5. URLは消える。消えた記録を残す

官公庁のページは改組・年度切り替え・サイトリニューアルで頻繁に失われる。
リンクが切れたとき、**「最初から無かった出典」と「当時は実在したが後に消えた出典」は
まったく別のもの**だが、ただ繋がらないだけでは区別が付かない。

`scripts/check_evidence_urls.js` が週次で全URLの生存を確認し、
`evidence_url_status.js` に「最後に到達できた日（last_ok）」を記録する。
リンクが切れた evidence には、詳細ページで
「⚠ リンク切れ（2026-10-06 時点では閲覧可）」と表示し、保存版への導線を出す。

**リンクが切れたというだけで evidence を削除しないこと。** 対応順序は次のとおり。

1. 移転先を探す（サイト内検索・`site:` 検索・省庁の新着一覧）
2. 見つかれば url を差し替える
3. 見つからなければ Internet Archive の保存版を url に入れる
4. どうしても見つからない場合のみ、記述の真偽を改めて検証する
   — **URLが消えたことは、記述が誤りだったことを意味しない**

### 3-6. ルールを書いたら、すり抜け方を考える

末尾一致で書いた検出パターンが語尾1語で破られた例（2-3）を忘れない。
新しい検出ルールを足したら、次を確認する。

- 部分一致で書いたか（`$` で閉じていないか）
- 既存データに対して実行して、想定外のものが引っかかる／引っかからないか
- **ルール追加の直後に既存データから新しい違反が出てくるのが正常**
  （今回、パターンを足すたびに当初の対象範囲の外から追加の違反が見つかった）

### 3-7. データを直したら3か所すべてに反映する

`data.js`（正本）/ `data_core.js`（一覧ページが読む）/ `politicians_base.json`（CSV元）。
`scripts/validate_core_sync.js` と `scripts/validate_base_sync.js` がCIで検証する。

### 3-8. 表示を変えたら実際に描画して確認する

データが正しくても表示が壊れていれば読者には届かない。1-4 がまさにそれだった。
HTMLを触ったら、ブラウザで実際に開いて確認する。

## 4. 入れた検査

| 検査 | 何を防ぐか |
|---|---|
| `validate_evidence_sources.js` | 実在しない文書名、資料体名のみの出典、同一議員内の重複、evidence と評価点の不一致（双方向） |
| `validate_data.py` | total / rank / axes の整合。ブランクのレコードは「すべてブランクか」を検査 |
| `validate_duplicates.js` | 読み＋院＋選挙区が一致する別レコード、氏名やURLの角かっこ残り |
| `validate_core_sync.js` | data.js と data_core.js の乖離 |
| `validate_base_sync.js` | data.js と politicians_base.json の乖離 |
| `check_evidence_urls.js` | 出典URLの生存（週次）。last_ok を記録し、リンク切れを Issue 化 |

### まだ埋まっていない穴

- **描画層のテストがない。** 出典がリンクとして描画されているか、JSエラーが出ていないかを
  自動で検査していない。1-4 と 1-6 はこれがあれば防げた
- **URLのない出典が172件残っている。** 出典名は実在するが特定のページを指していない

| | 修正前 | 修正後 |

| 議員総数 | 790人 | 781人 |
| evidence | 830件 | 552件 |

34人に追加した——**誤りは両方向に出ていた**。評価点が変わった議員は102人。

## 6. 教訓として一行で

**「出典欄が埋まっていること」と「出典が存在すること」は別であり、
「データが正しいこと」と「読者に正しく届いていること」もまた別である。**

この2つの取り違えが、今回のすべての欠陥の根にあった。
